# ประกันไปกับคุณ (insurGo)

**เปิดใช้งานได้ทันทีที่ → https://sarawut2206.github.io/insurGo/**

แอปมือถือแบบ PWA ที่ช่วยให้คนไทยเข้าใจความเสี่ยงของตัวเองก่อนตัดสินใจเรื่องประกัน
ติดตั้งลงหน้าจอโฮมได้ทั้ง iOS และ Android ทำงานได้แม้ไม่มีอินเทอร์เน็ต
และไม่ส่งข้อมูลออกนอกเครื่องผู้ใช้

> โครงการต้นแบบเพื่อนำเสนอแนวคิด — ไม่ใช่ผลิตภัณฑ์ประกันภัย และไม่ใช่คำแนะนำทางการเงิน

---

## ติดตั้งลงมือถือ

เปิด https://sarawut2206.github.io/insurGo/ บนมือถือ แล้ว

- **Android (Chrome):** เมนู ⋮ → ติดตั้งแอป / เพิ่มลงในหน้าจอหลัก
- **iPhone (Safari):** ปุ่มแชร์ → เพิ่มลงในหน้าจอโฮม

เมื่อติดตั้งแล้วจะเปิดเต็มจอเหมือนแอปทั่วไป ไม่มีแถบเบราว์เซอร์

---

## รันบนเครื่องตัวเอง

```bash
node server.js
```

เปิด `http://localhost:5173` — ตอนรันจะพิมพ์ IP ในวง Wi-Fi ออกมาด้วย
ให้มือถืออยู่ Wi-Fi เดียวกันแล้วเปิดลิงก์นั้นได้เลย

**ไม่มี dependency ภายนอกเลยแม้แต่ตัวเดียว** ไม่ต้อง `npm install` ไม่มี build step
ไม่เรียกฟอนต์หรือสคริปต์จาก CDN — ข้อมูลจึงไม่รั่วไปยังบุคคลที่สาม

## โครงสร้าง

```
index.html          7 หน้าจอในไฟล์เดียว สลับด้วย JS
manifest.json       ทำให้ติดตั้งลงหน้าจอโฮมได้
sw.js               service worker — ใช้ได้ตอนออฟไลน์
css/styles.css      รองรับโหมดสว่างและมืดอัตโนมัติ
js/questions.js     ชุดคำถาม 12 ข้อ พร้อมเหตุผลว่าถามไปทำไม
js/config.js        กฎและน้ำหนักคะแนน  ← ดูหัวข้อ "ข้อจำกัด" ด้านล่าง
js/engine.js        คำนวณคะแนน + สร้างคำอธิบาย
js/store.js         จัดเก็บข้อมูล + audit log
js/app.js           ควบคุม UI
server.js           static server ใช้ Node ล้วน สำหรับรันบนเครื่อง
```

## 7 หน้าจอ

| # | หน้าจอ | ทำอะไร |
|---|---|---|
| 1 | หน้าแรก | อธิบายว่าระบบทำอะไร และ **ไม่ทำอะไร** |
| 2 | ความยินยอม | แยก consent 3 ข้อตามวัตถุประสงค์ |
| 3 | แบบสอบถาม | 12 ข้อ แต่ละข้อบอกว่าถามไปทำไม ข้ามได้ทุกข้อ |
| 4 | กำลังประมวลผล | แสดง 5 ขั้นตอนที่ระบบทำ ไม่ใช่ spinner ลอย ๆ |
| 5 | Risk Profile | คะแนน 5 ด้าน + เหตุผล + ช่องว่าง + คำแนะนำป้องกัน + ข้อจำกัด |
| 6 | ส่งผู้เชี่ยวชาญ | แสดงสรุปให้ตรวจก่อนส่ง แล้วยืนยันอีกครั้ง |
| 7 | ข้อมูลของฉัน | ดู · ดาวน์โหลด · ลบข้อมูลทั้งหมด + audit log |

## แนวคิดที่ถูกทำให้เป็นโค้ดจริง

**Explainable AI** — ทุกคะแนนย้อนกลับไปหากฎที่ทำให้เกิดได้ ระบบเก็บเหตุผลไว้ตอนคำนวณ
ไม่ใช่คำนวณเสร็จแล้วค่อยหาคำอธิบายมาแปะทีหลัง หน้าผลลัพธ์แสดงปัจจัยหลัก 3 ข้อต่อด้าน
พร้อมแยกให้เห็นว่าอะไรทำให้ความเสี่ยง *สูงขึ้น* และอะไรที่ *ช่วยลด* อยู่แล้ว

**Human-in-the-loop** — ระบบไม่อนุมัติหรือปฏิเสธการรับประกัน ไม่คำนวณเบี้ย
หน้าส่งตรวจสอบแสดงชัดว่าผู้เชี่ยวชาญอยู่ตรงไหนของกระบวนการ

**PDPA — data minimisation** — เก็บ "ช่วง" ไม่เก็บตัวเลขจริง เช่น ถามช่วงรายได้ ไม่ถามเงินเดือน

**PDPA — consent แยกวัตถุประสงค์** — ถ้าไม่ยินยอมข้อมูลสุขภาพ ระบบ **ไม่ถามคำถามนั้นเลย**
(เหลือ 11 ข้อ) และไม่ประเมินด้านสุขภาพ พร้อมแจ้งผู้ใช้ตรง ๆ ว่าผลยังไม่ครอบคลุมส่วนนี้
ไม่ใช่เก็บไว้แล้วแค่ไม่แสดง

**ไม่เดาแทนผู้ใช้** — ข้อที่ข้ามจะไม่ถูกใส่ค่าเริ่มต้นให้ แต่ไปลด "ความเชื่อมั่น" ของผลแทน
และขึ้นคำเตือนว่าข้ามไปกี่ข้อ

**Audit log** — บันทึกทุกเหตุการณ์สำคัญพร้อมเวลา ให้ผู้ใช้ตรวจย้อนหลังได้

**ไม่แนะนำผลิตภัณฑ์ของบริษัทใด** — แนะนำเป็น *ประเภทความคุ้มครอง* เท่านั้น
ไม่ระบุชื่อบริษัท ไม่ระบุเบี้ย เพราะเบี้ยจริงต้องผ่านการพิจารณารับประกัน

## ข้อจำกัดที่ต้องรู้

**1. `js/config.js` เปิดเผยต่อสาธารณะ**
เมื่อโฮสต์เป็นเว็บ static กฎและน้ำหนักคะแนนทั้งหมดจะอ่านได้จาก
`https://sarawut2206.github.io/insurGo/js/config.js` โดยตรง
การ minify หรือ obfuscate ไม่ถือเป็นมาตรการรักษาความลับที่เพียงพอ
หากต้องการเก็บสูตรเป็นความลับ ต้องย้ายไปเป็น API ฝั่งเซิร์ฟเวอร์
แล้วให้ client รับกลับเฉพาะ *ผลลัพธ์ + เหตุผล*

**2. น้ำหนักคะแนนยังไม่ผ่านการตรวจสอบเชิงคณิตศาสตร์ประกันภัย**
ตั้งจากเหตุผลเชิงตรรกะ ไม่ได้มาจากข้อมูล actuarial จริง
ต้องให้ผู้เชี่ยวชาญตรวจก่อนนำไปใช้ให้คำแนะนำจริง

**3. ยังไม่ได้ทดสอบอคติ (bias testing)**
ต้องตรวจว่าผลลัพธ์ไม่เลือกปฏิบัติต่อกลุ่มใดอย่างไม่เป็นธรรม โดยเฉพาะปัจจัยอายุและอาชีพ

**4. ยังไม่มีโครงสร้างพื้นฐานด้านข้อมูลระดับ production**
ต้องเพิ่ม: นโยบายระยะเวลาเก็บข้อมูล · เข้ารหัสข้อมูลขณะพักและขณะส่ง ·
audit log ฝั่งเซิร์ฟเวอร์ที่ผู้ใช้แก้ไขไม่ได้ · ระบุผู้ควบคุมข้อมูล · ช่องทางใช้สิทธิของเจ้าของข้อมูล

## สถานะการทดสอบ

ทดสอบผ่านเบราว์เซอร์จริงที่ขนาดหน้าจอ 375×812 (มือถือ) ครบทุกเส้นทาง:

- ✅ consent gate — กดไปต่อไม่ได้ถ้าไม่ติ๊กข้อบังคับ
- ✅ แบบสอบถามครบ 12 ข้อ → ผลลัพธ์ถูกต้อง
- ✅ ไม่ยินยอมข้อมูลสุขภาพ → ถาม 11 ข้อ ไม่ประเมินด้านสุขภาพ ไม่มีคะแนนค้างในผลลัพธ์
- ✅ ข้ามคำถาม → ความเชื่อมั่นลดลง ขึ้นคำเตือน ไม่เดาค่าแทน
- ✅ ปุ่มส่งผู้เชี่ยวชาญถูกบล็อกเมื่อไม่ได้ให้ consent ข้อนั้น
- ✅ ดู / ดาวน์โหลด / ลบข้อมูล + audit log
- ✅ ไม่มี error ใน console
